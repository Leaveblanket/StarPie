# 注释规范（Comments）

> 本文是 [docs/architecture.md](../architecture.md) 的拆分文档；写、审或重构 `///` XML 注释与 `//` 行注释前读本篇。决策理由见 [ADR-0017](../adr/0017-comment-conventions.md)。

## 适用范围与角色分工

- 覆盖 C# 源文件（含测试工程）的 `///` XML 文档注释、`//` 行注释与文件头注释；XAML 注释遵守同一底线（不写溯源流水账）。
- 一句话原则：注释必须提供“代码本身看不出的**信息增量**”；没有增量就不写。

| 载体 | 内容 |
|---|---|
| `///` XML 文档注释 | API 契约与用法：做什么、何时用、注意什么（进入 IntelliSense，未来可进 API 文档） |
| `//` 行注释 / 文件头注释 | 代码内“为什么 / 约束 / 边界”，只写读代码看不出的部分 |
| git commit / `docs/adr/` / 架构叶子 | 变更史与“为什么”、难逆转决策理由、现行规则 |

## XML 文档注释

- **覆盖程度**：公共成员应有 `<summary>`；internal/private 成员仅在不自明或复杂时写，不为凑数而写。
- **`<summary>`**：一句话描述“做什么 / 返回什么 / 值代表什么”；超过一句的上下文移入 `<remarks>`。
- **`<remarks>`**：按需写约束、副作用、异常条件、使用前提、调用方职责等非显然信息。
- **参数与返回值**：`<param>` / `<typeparam>` / `<returns>` 描述含义，不复述名字或类型；契约内异常用 `<exception>` 描述触发条件。
- **引用**：一律 `<see cref="..."/>`、`<paramref name="..."/>`、`<seealso cref="..."/>`，不写裸 URL 或裸类型名。
- **属性**：`<summary>` 描述值语义，不机械写“获取或设置…”。
- **实现与派生**：优先 `<inheritdoc/>` 复用，不复制粘贴父注释。
- **语言**：中文；技术专名可保留英文原文；领域术语用 `CONTEXT.md` 规范词。

## 信息增量判据（写前自问）

写（代码 / 签名看不出的）：

- 返回值与属性的语义、`null` 语义、单位、顺序、线程与重入要求；
- 副作用、异常条件、前置条件与调用方职责；
- 一句话设计约束，例如“该标记由宿主组合根在装配前回填，应用代码只读不写”。

不写（签名或名字已经告诉读者的）：

- 复述成员名、参数名、显而易见类型或 getter 行为；
- 过程史与变更叙事（“自 X 收编”“随 Y 迁入 / 上提”“B2/#75 起”…）；
- 决策推理流水账与“无运行态状态”“无测试缝”类自我证明——理由归 ADR、叶子与 commit。

## 禁止清单（硬底线）

- 禁止一切编号化溯源：`#NN`、`T##`、`B#/#NN`、`H#`、`S#`、`M#`、`C#`、`ADR-NNNN`、`D#` 等；
- 禁止人名、日期、作者与“何人何时改动”记录；
- 禁止批次 / 路线 / 收编 / 迁入 / 上提等变更叙事；
- 禁止为“有注释”而写的空话 summary；
- 唯一允许的编号形式：`// TODO(#NN): …`（指向未来动作的短待办，不进 `///`）。

## 行注释（`//`）

- 只解释“为什么这样写 / 边界 / 易错点”，不复述代码在做什么；
- 禁止溯源流水账与批次史；文件头（如 `GlobalUsings.cs`）只保留当前必要事实；
- 区块分隔注释（`// --- 名称 ---`）允许但要短、不带任务号；
- 修改旧代码时，把被触碰的旧注释顺手改写为现行规范，不做范围外清理。

## 存量与迁移

- 存量注释（约 360 行 `///` + 180 行 `//` 携带溯源标记）**不追溯清理**，清理待办见 #84；
- 新旧并存属预期：新代码与“被修改到”的旧注释执行本规范，其余旧注释保持原样；
- 全仓清理单独成任务，逐条判断“约束留、史实删”，每批构建 + xUnit 验证。

## 样板（示例仅为规范说明，不表示代码已改动）

反例（存量风格摘要）：

```csharp
/// <summary>
/// 应用数据目录解析 (T16 自静态配置门面收编，ADR-0002)：dev 实例沙箱隔离与
/// legacy 目录迁移，供组合根构造 <see cref="JsonConfigService"/> 与共享图标资产（S1）
/// <see cref="IconAssets"/> 自定义图标目录使用。B2/#75 Core 抽取后随 S2 迁入共享内核：…
/// </summary>
```

正例（同类型注释的现行写法）：

```csharp
/// <summary>
/// 解析应用数据目录：正式实例使用 StarPie，dev 实例使用 StarPie-Dev。
/// </summary>
/// <remarks>
/// dev/正式分支由 <see cref="IsDevInstance"/> 决定；该标记由宿主组合根在装配前回填，
/// 应用代码只读不写。
/// </remarks>
```
