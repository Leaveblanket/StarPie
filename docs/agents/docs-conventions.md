# 文档写作文约

> 本文是 `docs/` 下全部文档（入口 `architecture.md`、架构叶子 `architecture/*.md`、`adr/*.md`、`agents/*.md`）的写作与维护口径正典；入口 §6 是本文的指针。
>
> **读者序位**：第一读者是 agent（按任务单篇加载、无记忆、照字面执行），第二读者是人类维护者。两者冲突时以「让 agent 能正确行动」为准；人类侧对"为什么"的需求由 ADR 满足。

## 1. 失真优先于重复

与代码不符的陈述是**错误**，不是冗余：读者照它行动就会做错事，而 agent 不会像人那样起疑核查。发现失真即修，优先级高于任何去重。

- **正例**：`layout.md` §1 树与磁盘一致，且由 `DocInvariantTests` 机械守护路径存在性。
- **反例**：`layout.md` 曾自称「当前代码与正典一致」，而树缺 `StarPie.Host/HostServices/` 等实际目录。

凡可机械核验的失真一律落断言：路径存在性、类型名存在性、常量归属、ADR 头部状态。不可机械核验的（"这段是否重抄了别人的正典"）留给评审。

## 2. 零流水

文档不承载时间维度。历史、批次、"已落地"、被取代的过程一律归 git 与 issue。

- **正例**：「四集不得引用旧集（跨集只经 SDK）」——只写现行约束。
- **反例**：「旧 15 集已全部撤销」「无旧集残留」「此前按 X 处理，该口径已废」——读者（尤其 agent）会把历史当现状推理。

换皮写法同样是流水：「无旧集与壳工程」不出现"已"字，但与「已撤销」是同一件事。

## 3. 正典唯一 + 引用就近

同一事实只有一处正典：

- **清单型事实**（程序集地图与依赖方向、导航槽位表、页面映射表、DI 注册清单、可见性先例）只许正典处写全，他处引用不抄写；
- **约束型规则**（VM 不得引用 WPF 表现类型、Composition 唯一解析点、对话框唯一形态、`config.json` 向后兼容）正典处写全，他处留一句摘要加引用。

别处留多少由**缺失是否致误**决定：

- 读者会因这一句缺失而**做错动作** → 就地写全（禁令、边界、例外口径，哪怕显得重复）；
- 只是不知道去哪查细则 → 指针化。

- **正例**：`prohibitions.md` 每条禁令自带可执行判据（点名具体类型），只在末尾指向细则。
- **反例**：`layering.md` 抄写 `assemblies.md` §7 的可见性先例——它既不是禁令也不是边界，缺了它读者不会做错事，只会不知道去哪查。

## 4. 反例就地，正例留在本域正典

边界示例（反例）≤3 行就地保留——反例就是边界，是读者最容易踩空的地方。教学式正例留在它所属领域的正典叶（如代码注释的正例住 `comments.md`），**不必**迁进本文约：本文约只收**文档写作**自身的正例。

## 5. 元规则归位

文档体系自身的规则（怎么写规范、什么进 ADR、什么进 CONTEXT）只住本文约，不进领域页。

- **反例**：`prohibitions.md` 末条「不得把 ADR 推理复制进规范文档」——架构禁令页里混进了文档规则。

## 6. 目标态分治

- **叶子**：允许目标态，但只许写在一个「目标态与差距」节里，正文其余部分是纯 as-built；行内标记只用 `规划：` / `as-built：`，不得用 `目标态 =` 这类等号异体。
- **ADR**：不承载"待建设清单"——它记的是当时的决策。目标态写进 ADR 后被现实推翻、又无人回改，ADR-0023 的「程序集目标态 = 15」就是实例。

## 7. ADR 特殊性

ADR 不适用执行者口径：它是"要不要推翻这个决策"的记录，四要素（问题 / 选择 / 为什么 / 代价）必须完整。只删三类：重抄的现行规范、变更史与取证纪要、死引用与过期快照。

**理由只住 ADR，规则只住规范**：不得把 ADR 的推理复制进规范文档——规范文档只保留规则与引用。

**编号身份不可动**：不合并、不改号、不删号——全仓约 392 处 `ADR-NNNN` 引用横跨 83 个文件，并号会让引用与 git 历史错位。被取代只改头部 `Superseded by NNN`，正文留残值。

## 8. 度量

不记行数。报三个数：**失真项**（与代码不符的断言）、**重复项**（同一事实的非正典陈述）、**越界项**（现状/目标态混排、元规则错位）。

行数是坏指标：它会诱导把约束型规则也指针化（可用性反而下降），也会让"难写"成为删规范的理由；而结构化重排（宽表格改短表加分点）会增加行数却降低误读。

## 9. 红线

下列内容不因精简而移除：`CONTEXT.md` 术语条目、入口 §2 路由表结构、`DocInvariantTests` 断言本身（失败先修文档，不放宽断言）、已声明正典的清单。

## 10. 豁免

机检的白名单只能写在本文的「豁免清单」节，每条带一句理由；不得硬编码在测试代码里——否则豁免变成隐形的，下次没人知道为什么放行。

## 维护义务

1. 规范变更只改**对应叶子**；新增主题先建叶子，并在入口 §2 路由表登记一行。
2. 新增决策满足三条件（难逆转 / 无上下文会惊讶 / 真实权衡）时，先新增 ADR 再把结论回填对应叶子；否则只改叶子。
3. 叶子增删与文件路径变化时同步入口（§1 体系表、§2 路由表）；仓库目录树正典在 `layout.md` §1，入口只留指针。
4. ADR 头部必带状态（`Active` / `Superseded by NNN` / `Active（部分被 NNN 修订）`）与修订指针——状态只写头部，其它文档不复制。
5. `CONTEXT.md` 只收领域术语；架构词（宿主 / 模块 / 程序集 / M1–M5 等）正典在 `modules.md` 与 `assemblies.md`。
6. 新增用户可见文案补齐四语言键值（zh-CN / zh-TW / en / ja），见 `localization.md`。
7. 任务型盘点（登记表 / 待清理项 / 进度清单）带"关闭即删"义务：盘点完成即删，留痕挂对应 issue，不驻留规范叶。
8. 入口不索引 ADR 状态、不复制叶子内容：路由表每行一个文件、每个叶子恰好一行；查状态读 ADR 文件头，查规范读叶子。
9. 验证义务与测试策略分层（提交级门、合入门与免除口径）见 `git-commits.md`——该文是唯一正典，本文与叶子不复制。

## 机检口径

> 由 `StarPie.Tests/DocInvariantTests.cs` 直接读取（断言 `叶子不残留完成态流水与日期快照`）。
> 增删即改机检口径——加词前先确认现有文档能全绿，否则先清理再加锁。`#` 开头为注释行。

```text
# 完成态断言（ERE）
已[^，。；、]{0,6}(删除|移除|撤销|清零|退役|落地|废)
# 换皮流水写法（ERE）
无旧集|旧集残留|不再有|不再持有|不再独立成集
# 等号式状态标记（ERE）
目标态\s*=|规划\s*=
```

机检是**代理指标**：它抓得住完成态断言与已知的换皮写法，抓不住语义级的历史叙事与人称化的过程描述——那一半靠评审，判据是本文第 2 条。

## 豁免清单

> 一行一条：`<token>  # <理由>`。当前为空——as-built 类型名锁尚未启用（见下节）。

```text
# 一行一条：<token>  # <理由>
```

## 归属断言

> 一行一条：`<名字> @ <源码相对路径>`——该名字必须仍声明在该文件里（防「文档把常量归给别的类型」这类失真）。

```text
AutoSaveDelay @ StarPie.Host/Configuration/SettingsSaveOrchestrator.cs
```
