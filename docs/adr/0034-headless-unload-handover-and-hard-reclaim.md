# headless 卸载三条款：装载结果交接即清空强引用、在途未归零中止于危险区之前、硬判 ALC 与程序集回收

> Status: Active（决策 3 的适用范围被 [ADR-0035](0035-wpf-host-plugin-assembly-reclaim-downgrade.md) 修订）
>
> 关联：#124。契约正典：plugins.md §8。**本 ADR 只覆盖 headless 插件**；UI 插件的卸载语义见
> [ADR-0030](0030-ui-plugin-unload-semantics-downgrade.md)（不承诺 ALC 与程序集回收）。

## 动机

1. **回收判定与"谁还持有插件对象"是同一件事**：headless 插件承诺 ALC 与程序集真回收，判据是
   `WeakReference` 全死；只要装载结果（或装载管线的局部变量）还被调用方持有，判定必然失败。把这条
   写成"调用方自律"的约定，等于把验收交给纪律——一次真实的残留会被记账成"插件泄漏"。
2. **在途调用是危险区的开关**：`StopAsync`、服务作用域释放、`ALC.Unload()` 都假定插件代码已不再运行。
   在途未归零就继续释放作用域，插件的回调会落在已释放的账本与宿主服务上，故障从"卸载失败"扩散为
   "宿主状态未知"。
3. **回收断言只对 headless 插件成立**：UI 插件一旦触及 WPF 类型或 BAML，程序集在进程内不可回收
   （ADR-0030 的取证）。若把 ALC 回收写成管线的无条件断言，UI 插件接入时会得到必然失败的验收。
4. **失败终态只有隔离**：卸载的任一步失败都不许谎报成功，也不许把隔离态当作可继续卸载的中间态——
   需要把这三条落成状态机可达路径与结果契约，而不是留在实现细节里。

## Considered Options

- **让调用方"保证不再持有"装载结果** → 否。约定不可验证，违反时表现为"回收判定失败 + 隔离"，
  把调用方的持有错误记账到插件头上。
- **在途未归零时继续释放作用域（尽力卸载）** → 否。危险区之后的步骤都假设插件代码已停；继续走
  等于让插件在已释放的宿主服务上执行。
- **在途未归零按卸载成功处理（下次再说）** → 否。谎报成功；用户可见的"已停用"与实际状态不符。
- **交接即清空装载结果的强引用 + 未归零中止于危险区之前 + headless 硬判回收** → 采纳。

## Decision

1. **卸载输入是交接对象**：`PluginUnloadRequest.FromLoaded(PluginLoadResult)` 是插件对象所有权的唯一
   转移点；交接时装载结果持有的入口实例、ALC 与服务作用域三条强引用被清空（`ReleaseForUnload`），
   装载结果对插件集不再有可达面。回收判定要求请求自身先清空强引用，且 `ALC.Unload()` 的调用帧**退出后**
   再做（Debug 下调用帧的临时栈槽会 root ALC，使判定误报"仍存活"）。
2. **在途未归零中止于危险区之前**：排空超时或取消 → 能力条目已摘除（不再对外可见）、但不释放服务
   作用域、不 `ALC.Unload()`，直接按隔离收口。管线不自动续做——要收口只能等下一次显式安全点
   （重载或重启）。
3. **headless 硬判回收，UI 降级**：`ALC.Unload()` 之后对入口实例、ALC 与入口程序集的 `WeakReference`
   做有界重试 GC 判定，任一存活 → 隔离 + 重启提示。本管线只服务 headless 插件；UI 插件接入时按
   ADR-0030 不判 ALC 与程序集回收，存活只记诊断。
4. **并发熔断隔离不使卸载抛异常**：卸载中途状态机被调用守卫熔断置为隔离时，跳过后继转移、照常完成
   资源回收，结果如实返回"隔离 + 既有原因"；隔离与已卸载一样是终态，不再接受任何转移。
5. **已隔离的插件也能在安全点回收资源**：隔离终态不构成"资源滞留到重启"的理由——同一管线可对
   隔离插件执行排空与回收步骤，结果仍是隔离、不改写既有隔离原因，也不谎报已卸载。

## Consequences

- 装载结果与卸载请求都是一次性的：装载结果在交接后只剩结果三态、失败原因与状态机；卸载请求在交出
  ALC 后自清。两者都不再是插件对象的长生命周期持有者。
- 卸载的每一步与回收判定都进诊断清单，成为管理面与排障的唯一事实来源；调用方无法把它改写为"成功"。
- 本 ADR 只约束内存态：隔离的持久化与用户可见的重试/停用入口不在其中。
- UI 插件接入本管线前必须先补"UI 释放 + 泄漏扫描"编排（plugins.md §8 第 4/5 步），否则其回收判定会以
  ADR-0030 已证否的假设失败。
