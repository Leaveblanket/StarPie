# 常驻壳层与瞬态设置台租户：托盘态只保留托盘与手势，设置台按需创建并随关闭释放

> Status: Active（决策 3 的作用域要求被 [ADR-0048](0048-theme-state-and-language-dictionary-residency.md) 修订）
>
> 本文修订 [ADR-0003](0003-application-host-restructure.md) 与
> [ADR-0011](0011-composition-apphost-split.md) 对宿主编排的单对象假设：`AppHost` 承担的两条生命周期
> （常驻编排与设置台宿主）拆为常驻壳层与瞬态租户。
> 契约正典：`docs/architecture/host.md`、`docs/architecture/shell.md`。

## 动机

1. **托盘态承担着完整的设置台对象图**：设置台（主窗口 + 侧栏 + 五页 View/VM）在启动时全部构造并随进程
   常驻；关窗只是隐藏窗口，进托盘出账只切断当前页视图——窗口本体、页面 VM 与其订阅永不释放。而关窗
   驻留是产品的主要停留状态，常驻内存因此被设置台长期占据。
2. **页面 VM 是容器单例且在启动期被 eager 解析**：组合根遍历导航目录逐个解析页面 VM，新增页面自动纳入
   启动构造；VM 构造即订阅导入广播、落盘请求与本地化事件，这些订阅同样随进程常驻。
3. **手动的 GC 收敛对可达对象无效**：`MemoryOptimizer` 的两轮全量压缩只能回收不可达对象；`GC.Collect`
   不回收仍被托管代码引用的对象。在视觉树、事件源或容器单例仍持引用时，反复 GC 不产生实质收益——瓶颈
   在引用关系，不在回收时机。
4. **托盘与手势本就不依赖设置台**：托盘自建 `HwndSource`（原生窗口，非 WPF `Window`），轮盘窗口本就每次
   手势现建现毁。"常驻只需托盘 + 手势"在产品上成立，只是被宿主类的单一编排挡住了。

## 取证（结论与判据）

- **可达引用的三处来源**：宿主持有的主窗口字段、对话框服务持有的 Owner 强引用、页面 VM 的容器单例注册
  与启动期 eager 解析；退出态与托盘动作寄居在页面 VM 上——设置台"可回收"必须同时处理窗口、页面 VM
  与订阅，缺一处就不成立。
- **`Application.MainWindow` 的钉住风险**：该属性会被自动设为进程中第一个实例化的 `Window` 并长期持有
  强引用，且"置空后是否被后续窗口重新赋值"无文档保证；在瞬态窗口成为首窗的进程里，某个已关闭窗口
  可能永远不可回收——这是决策 6 常驻锚窗口的由来。
- **已显示窗口关闭后是回收延迟，不是运行时保留**：`Close()` 后 HWND 已销毁、已退出 `Application.Windows`、
  `MainWindow` 已改指，但 `Window` 托管对象会存活到下一次 gen2 回收（无强根）；任意时刻堆上至多剩
  最近一次关闭的那一份。已关闭窗口在回收前仍可达其视图树与 `DataContext`——这正是收尾纪律要主动
  丢弃二者的原因（决策 5）。
- **主题依赖的边界**：轮盘只用系统深浅色读数（无状态探针），托盘消费的也只是一个 `Func<bool>`；
  主题状态、字典槽整项替换与系统监听器的消费方全在设置台路径——常驻侧因此只需一个探针（决策 3）。
- **轮盘与插件页天然兼容瞬态设置台**：轮盘 XAML 用字面色值与窗口本地资源、不依赖应用级资源字典；
  导航执行缝对插件页调注册工厂，插件页视图模型本就每次导航新建。

## Considered Options

- **继续加深 GC 收敛或恢复工作集裁剪** → 否。GC 不回收可达对象；工作集裁剪已随分层常驻整体删除，
  只改变 OS 记账口径，不改变真实占用。
- **双进程（后台托盘进程 + 按需 UI 进程）** → 否。需跨进程同步配置与本地化、拆分单实例闸门、重新定义
  提权重启与插件装载归属，并把托盘与手势的可靠性绑到进程间通信上；其收益是故障隔离，与"降低单进程
  常驻"的目标不匹配。
- **设置台改瞬态但页面 VM 保持常驻** → 否。窗口可回收而页面 VM 及其订阅仍常驻，"设置台可回收"名不
  副实。
- **不经缓存、每次导航新建页面 VM** → 否。来回切页丢失页内状态，属行为回归。
- **常驻壳层 + 瞬态设置台租户 + 会话内页面 VM 缓存** → 采纳。

## Decision

1. **单进程内按生命周期划分**：主壳层（托盘、手势管线、核心服务、插件运行时、应用级资源字典、单实例
   闸门、退出编排）常驻至进程结束；设置台为按需创建、关闭即销毁的租户；轮盘维持每次手势一个实例。
2. **常驻判据**：设置台关闭期间，从常驻事件源（鼠标钩子、托盘回调）沿调用链可达者必须常驻。据此，
   配置服务（且必须是同一实例）、本地化服务与图标资产服务本体常驻；图标位图与列表缓存、主题服务的
   有状态部件不据此常驻。
3. **深色判定与主题服务解耦**：常驻侧只持一个读系统深浅色的无状态探针（`Func<bool>`），轮盘与托盘消费
   该探针；主题状态、字典槽替换与系统监听随设置台作用域。
4. **设置台会话内缓存页面 VM**：同一会话内保留实例以维持切页状态，会话结束整批释放；页面 VM 须实现成对
   退订，由租户释放时统一执行。
5. **瞬态窗口收尾纪律集中一处**：清窗口动画 → 丢弃窗口内容与 DataContext → `Close()` →
   排空 Dispatcher（排到 `ApplicationIdle`，覆盖已显示窗口的句柄销毁与布局清理载荷）→ 处理
   `Application.MainWindow` → 丢弃强引用；设置台、轮盘、对话框与插件窗口共用同一实现，不分散。
      丢弃内容与 DataContext 是必需步骤：窗口对象在回收发生前一直留在堆上、回收时机不可控，
      尚未回收的窗口不得顺带挂住整棵视图树与 VM 树。
6. **`MainWindow` 由常驻锚窗口持有**：留一个永不显示的隐藏窗口长期持有 `Application.MainWindow`，使任何
   瞬态窗口都不可能被自动赋值钉住。该做法不依赖自动赋值条件的精确语义。
7. **常驻职责不得寄居在瞬态对象上**：单实例恢复消息的接收端驻常驻侧；进程级主题状态的确立、退出态、
   托盘气泡与提权重启归壳层；设置台窗口不再是常驻职责的宿主。
8. **可回收性作为可判定验收**：以"常驻期仅剩锚窗口""关闭后窗口/视图/页面 VM 的弱引用全部死亡""开关
   循环后堆与窗口计数不单调增长"为判据，按既有 STA 夹具与弱引用断言方式验证。窗口与视图树的对象级弱引用
   判定按取证一段的实测边界让位于结构判据（全局窗口集合、主窗口属性、窗口已关闭卸载）与常驻内存测量；
   会话 VM 的弱引用判定照常执行。
9. **不新增 SDK 契约与解析点例外**：深色探针用 `Func<bool>`；页面 VM 解析仍只经既有导航执行缝。

## Consequences

- **关闭即丢弃未提交的页内临时状态**：已落盘状态不受影响（释放序列首步为落盘冲刷），但半输入的页内编辑
  会随租户销毁丢失。
- **首次打开设置台变冷**：既有启动预热只覆盖轮盘核心路径，不覆盖设置台；启动耗时下降与之互为代价。
- **启动期不再 eager 构造页面 VM**：页面 VM 在首次进入该页时构造。
- **页面 VM 的成对退订成为正确性前提**：漏一处即每次开关泄漏一份；验证依赖逐项清点与弱引用断言，
  不能只靠人工核对。
- **既有决策的结论不变**：ADR-0009 的 code-behind 白名单语义保持（窗口关闭改语义仍属生命周期接线项）；
  ADR-0016 的模块归属不变（拆分发生在宿主壳模块内部）；ADR-0030/0035 的插件回收边界不变（插件释放
  另议）；ADR-0031/0032 的 e2e 静默形态需按新窗口生命周期回归。
