# 测试范围:只留核心逻辑检查,环境耦合面整体下线

**状态**:accepted

`StarPie.Tests` 的 xUnit 套件曾覆盖四集全部行为(75 个文件 / 802 个测试方法),其中约两成是环境耦合用例:真实 `AssemblyLoadContext` 装载与卸载、`GC.Collect` 后的弱引用回收判定、真实 WPF 窗口与 STA 消息循环、进程内 `Mutex` 接管握手、临时目录里的插件包装载。它们按生产路径复现基础设施,慢、必须全局串行,而失败常常指向测试环境而非产品缺陷。决定:**xUnit 只保留核心逻辑检查**——纯规则与算法、ViewModel 的状态与编排逻辑、插件域的纯契约(生命周期状态机 / 准入判定 / 能力表 / 清单解析);环境耦合用例连同其夹具(STA harness、插件夹具集合、越权 UI 负对照)整体删除,真实装载 / 卸载、UI 托管、窗口与托盘生命周期的覆盖交 `tests/` 的 pywinauto e2e 与人工冒烟承担。被删用例在 git 历史里可原样取回。

## 考虑过的方案

- **域裁剪(窄)**:只留内核算法(轮盘手势 / 几何 / 路由 / 解析 / 配色),ViewModel 与插件域全砍。否决:ViewModel 是设置与轮盘手势逻辑的实际承载,砍掉等于把最易改坏的部分交给 e2e 兜底。
- **属性裁剪(采纳)**:按「逻辑 vs 集成」切——无环境副作用的确定性检查留下,真实基础设施(ALC / 窗口 / 进程 / 系统原语)的复现下线。
- **两者交集**:域属内核且属性确定。否决:与域裁剪同弊。

隔离临时目录的 I/O 用例(配置读写边界、清单校验、审核裁决)归「逻辑」侧予以保留:它们自封闭、确定,守的是规则引擎而非基础设施。

## 后果

- 插件 UI 卸载矩阵(plugins.md §7.2–§7.4 原「测试矩阵」条款)不再有自动化守护,该条款已改写为实况;`PluginUiLeakVerifier` 作为生产诊断入口保留,硬判 / 降级判据留在 `PluginReclaimPolicy` 与源码注释。
- `PluginServiceScope` 释放后句柄账本清零、插件自定义异常不 root 插件集两项 HostServices 侧判定仍在 xUnit 内——它们是纯对象图断言,不碰 ALC 与窗口。
- 套件保持全局串行:保留用例里的弱引用回收断言(VM / 服务作用域释放)经不起并发扰动。
- `NSubstitute` 与两个 `Package.targets` 导入(把随包插件复制进测试输出)失去用途,随之下线;引用已删的 `docs/architecture/testing.md` 的两处悬空注释一并移除。
- 早前一轮已下线的看守类机械断言(四集边界 / 导出面白名单 / 资源键 / 文档不变量)不再补回:测试范围就是本文描述的「核心逻辑」,架构文档与各 csproj 注释里残留的「由 xUnit 机械断言」说法按此改写为实况。
