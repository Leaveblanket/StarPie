# 轮盘配色模块归属与外观设置模块化拆分（界面主题模块边界 + 预设名语义）

> Status: Active（决策已实施，现状见 `docs/architecture/wheel.md` / `interface-theme.md` / `modules.md`）

## 动机

本地化/主题推翻重构把轮盘配色与主题风格划出范围外暂存；本 ADR 为两者定稿模块归属、外观设置 VM 拆分目标形态与自定义预设名显示语义。核心张力：轮盘配色是“用户数据 + 轮盘渲染消费”，界面主题是“窗口 chrome 令牌体系”，二者长期共用 `Theme` 一词互相污染。

## Considered Options

### 模块命名与候选类别
- **「主题配色模块」伞形/归并**：把界面主题子系统改名或新建泛化配色体系统一收纳两者。否决理由：普通语义「主题配色」同时涵盖窗口主题与轮盘配色，会在命名层复吸已按消费方切开的模块；与 CONTEXT「界面主题」的 Avoid 词冲突；代码层更名纯 churn。
- **「界面主题模块」文档级正名**：架构文档/讨论用语正式称界面主题子系统为界面主题模块；代码标识符与 CONTEXT 领域术语不动；不建伞形类别。

→ 选 **界面主题模块，文档级正名，不建伞形**。

### 轮盘配色机制归属
- **令牌化进 `Themes/*.xaml`、复用主题整项替换**：否决——自定义预设是运行时用户数据，不可能编译期 XAML 化，固定方案令牌化会造成“静态字典 + 数据预设”双轨；轮盘是每手势瞬态实例，无“已开轮盘跟随切换”语义；会污染 chrome 令牌 key 集；纯视觉渲染契约会被资源机制反耦合。
- **扩展 `IThemeService` 统一托管轮盘配色**：否决——`IThemeService` 语义已锁死为窗口界面主题单一入口；塞入轮盘配色会让主窗口/对话框等订阅方收到无关变更；轮盘配色无常驻运行时状态可广播。
- **消费方原则归轮盘模块**：轮盘配色唯一运行时消费者是轮盘渲染器与预览，数据与解析留在轮盘侧。

→ 选 **消费方原则（归轮盘模块）**；明确否决令牌化与 ThemeService 托管两条路。

### 轮盘配色模块粒度
- **独立顶层模块**：否决——只有一个消费者族，规模不足以撑起顶层模块；出现第二个消费者时再提升。
- **模块级并入轮盘模块 + 类型级分离**：配色目录/解析器独立成类型，渲染器工厂与各风格渲染器保持独立，由轮盘渲染管线组合。

→ 选 **并入轮盘模块、类型级分离**。

### 外观 VM 拆分形态
- **只拆界面主题（形态 A）**：改动小，但轮盘侧仍整块驻留页面 VM，模块化不彻底。
- **双拆 + 薄聚合页 VM（形态 B）**：界面主题与轮盘外观各自拥有设置子 VM，页面 VM 只做聚合、导入重挂编排与消息广播。
- **不建新类型、仅文档声明（形态 C）**：不实现“可独立修改”目标。

→ 选 **形态 B**。

### View 对 VM 感知的收窄
- **保留事件 + DataContext 强转读状态（现状）**：页面 code-behind 仍手写模块状态读写。
- **状态驱动 + 依赖倒置**：界面主题应用改消息驱动（VM 写配置后发布消息，主视图订阅执行）；预览重绘消息补全；页面 code-behind 只剩 DataContext 一次桥接与消息订阅（ADR-0009 白名单），不读模块状态。
- **零 code-behind**：最彻底但改动面最大，与 ADR-0009“允许少量 code-behind”的既有取舍重复，列为未来演进方向。

→ 选 **状态驱动 + 依赖倒置**。

### 预览渲染器输入形态
- **直依赖 `WheelAppearanceSettingsViewModel`**：简单，但渲染器认具体 VM。
- **只读接口 `IWheelAppearanceState`**：依赖倒置，测试/替换友好。
- **不可变快照**：解耦最强，但 hover 交互需重取或缓存几何，复杂度上升。

→ 选 **只读接口 `IWheelAppearanceState`**。

### 自定义预设名显示语义
- **名称本地化展示**：否决——预设名是用户数据。
- **名称原样 + 周围文案键化**：下拉格式键固定，`{0}` 原样插入用户数据、永不翻译；保存/重命名/删除的标题、提示、确认、成功信息、空名校验、默认名模板全部键化；默认名建议用本地化模板 + 时间戳（创建时语言定格，保存后为数据）；保存/重命名 trim 后入库、空名拒绝；允许重名、不设长度上限，截断交 ComboBox。

→ 整包采纳。

## Decision

1. **文档级模块正名**：壳层界面主题子系统在架构文档中称「界面主题模块」；代码标识符（`IThemeService`/`AppThemePaletteManager`/`Services/Shell`/`Views/Styles/Themes/*.xaml`）与 CONTEXT 领域术语不改；不建立「主题配色模块」伞形类别。
2. **归类判据**：模块归属 = 运行时效用/消费方；轮盘配色与界面主题各自独立，互不隶属。
3. **轮盘配色归属**：属轮盘模块；模块级并入、类型级分离——配色目录（系统预设数据）与解析器独立成类型，渲染器工厂与风格渲染器保持独立；不向 `Themes/*.xaml` 添加轮盘 key；不扩展 `IThemeService` 托管轮盘配色状态。
4. **轮盘配色能力边界**：配置数据 + 解析 + 设置编排；画刷构建留在视图/渲染层，Models 保持 WPF-free，解析输出 hex/`RgbColor` 值。
5. **轮盘外观配置面**：外观页去掉界面主题后的全部设置（主题风格、几何、排版、轮盘配色、光晕、核图标、背景纹理）同属轮盘模块配置面。
6. **外观 VM 拆分目标形态（形态 B）**：
   - `InterfaceThemeSettingsViewModel`（界面主题模块设置子 VM）：独占界面主题透传与驻留主题选项目录（语言切换重建；随容器 Dispose 退订）；
   - `WheelAppearanceSettingsViewModel`（轮盘模块设置子 VM）：承接全部轮盘外观状态与命令（含预览依赖与预设 CRUD）；
   - `AppearanceSettingsViewModel` 收为薄聚合页 VM：暴露两个子 VM、配置导入后重挂编排与 Dispose 链；
   - 设置子 VM 物理落位页面 VM 命名空间（沿用单例规范），不新增导航页；运行时轮盘 VM 命名空间不放单例设置 VM。
7. **View 收窄（状态驱动 + 依赖倒置）**：界面主题应用经 `AppThemeChangedMessage` 由主视图（壳层白名单）订阅执行；预览重绘补发预览失效消息；页面删除选择变更事件处理器，code-behind 仅保留 DataContext 桥接与消息订阅（ADR-0009 白名单）。
8. **预览输入**：定义只读接口 `IWheelAppearanceState`，由 `WheelAppearanceSettingsViewModel` 实现；预览渲染器只依赖该接口。
9. **预设名语义定稿**：见 Considered Options「自定义预设名显示语义」整包。

## Consequences

- ADR-0013 决策 8「轮盘配色范围外暂存」由本 ADR 收口。
- CONTEXT 不收录「界面主题模块」——它是架构模块名而非领域术语（领域词「界面主题/轮盘配色/主题风格」已在词汇表）。
- 术语终态（WheelPalette/WheelStyle/界面主题）与配置键迁移见 [ADR-0024](./0024-terminology-final-state-and-full-rename.md)。
