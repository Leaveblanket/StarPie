# dev 实例不与正式版并行：互斥收敛单一名、触发键回归右键

> Status: Active
>
> 修订 [ADR-0037](0037-dev-instance-flag-by-build-config.md)：其「构建配置定死 dev 判定」不变，五个行为分支中的互斥名与触发键两支移除。

## 动机

ADR-0037 确认不存在「Release 构建 + dev 沙箱」场景后，dev 实例五个行为分支中仍有两个只为「与正式版同时运行」存在：独立互斥名（异型并行、同型互斥）与中键触发（避让常驻正式版的右键手势）。实际使用确认开发时正式版不常驻运行——开发前先退出正式版即可，两个分支没有消费场景；而 dev 与正式版共用一把全机互斥反而更符合预期：同时启动时后启动方按「已有实例」路径置前退出，不会出现两个实例争抢全局鼠标钩子。

## Considered Options

- **保留双互斥名与中键触发** → 否。以"将来可能并行开发"为由保留无场景分支，与既有裁决（无并行需求）矛盾。
- **只删互斥双名、保留中键** → 否。中键触发同样仅并行需要；保留会让 dev 形态多一条无源分支。
- **单一互斥名 + 右键触发** → 采纳。

## Decision

1. 单实例互斥收敛为**单一全机命名互斥**（`Global\StarPie_SingleInstance_Mutex_…`），dev 与正式实例同闸；`DevInstance.MutexName` 删除，互斥名收进 `App` 私有常量。
2. 手势触发回归右键：`MouseHook` 删除 dev 中键分支（触发消息选择与中键补发），dev 与正式版行为一致。
3. dev 实例保留配置沙箱、自启注册表保护、`(Dev)` 可见标记——三者不依赖并行（保护的是"正式版已安装"这一事实）。

## Consequences

- 开发时若正式版在运行，`dotnet run` 命中「已有实例」路径（置前其设置窗口后退出）——开发前需先退出正式版，这是「不并行」裁决的直接体现。
- 全局鼠标钩子同时只由一个实例持有，右键手势不会出现双轮盘争抢。
- e2e 不受影响：`--test-instance`/`--allow-multiple` 跳过互斥，`LOCALAPPDATA` 沙盒隔离配置，被测 Release 构建行为零变化。
