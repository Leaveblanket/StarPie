# 主题状态与语言字典维持常驻：收益受托管堆天花板封顶，不值当字典摘挂的时序风险

> Status: Active
>
> 本文修订 [ADR-0039](0039-resident-shell-and-transient-settings-console.md) 决策 3：撤回其中
> 「主题状态、字典槽替换与系统监听随设置台作用域」这一**正面要求**，三者维持进程级常驻，
> 应用级语言字典同样维持 Application 级。
> **ADR-0039 决策 2 的常驻判据本身不变**——该判据判定「哪些必须常驻」，不判定「哪些不得常驻」；
> 决策 3 中「深浅色消费方一律经无状态 `Func<bool>` 探针」的已实施部分继续有效。

## 动机

1. **决策 3 含两条性质不同的断言，只有前一条是判据的正确应用**：无状态 `Func<bool>` 深浅色探针
   说的是「常驻侧不得依赖瞬态对象」，与判据方向一致；而「主题状态、字典槽替换与系统监听随设置台
   作用域」是把判据的**反面**当成了正面要求——判据只说明这些部件不**必须**常驻，
   并未要求其不得常驻。把「不必」读成「不得」，是这次作用域化要求的来源。
2. **正面要求的收益被托管堆天花板封顶**：常驻态实测的托管堆 live 总量在 4 MB 量级，
   多次开→关循环后的增量可忽略（约 4 KB/循环，WPF/XAML 基础设施的稳态抖动）；同期进程的
   提交私有字节与工作集比托管堆高 1–2 个数量级，且其水线在早期一次性上抬后持平、不随开关循环
   增长——即观察到的常驻重量在原生/WPF 侧，不在托管侧。待收的两项都住在托管堆内：
   调色板字典的活动槽与适配器缓存（至多五套 XAML 令牌字典）、当前语言一份约 267 键的语言字典。
   即便全部移出，收益也仍被该天花板压住。
3. **正面要求的代价落在主题装配的时序上**：活动主题槽靠 `Source` 含 `/Themes/` 识别
   （[`AppThemePaletteManager`](../architecture/interface-theme.md)），插件资源根合并进同一
   `MergedDictionaries` 集合；在设置台开关上摘挂字典，等于在渲染/主题装配路径引入时序耦合。
   风险落在装配路径、收益在天花板内，两者不成比例。
4. **语言字典是常驻服务的投影，不是独立状态**：它按当前语言重建，数据源是常驻本地化服务的
   `EnumerateCurrentEntries()`，切语原地 `Clear` 重建（[localization.md](../architecture/localization.md)）。
   随控制台作用域化不释放任何独占对象，只会新增「设置台关闭期间声明式文案无源」这一边界。

## Considered Options

- **实施决策 3：主题状态、字典槽替换与系统监听收进设置台作用域** → 否。其收益在托管堆天花板内，
  其代价在主题装配的时序上；且它不为任何常驻判据所要求。改动面大、收益面在天花板内。
- **连无状态探针一并回退为对 `IThemeService` 的服务依赖** → 否。探针那条是判据的正确应用：
  常驻侧（轮盘、托盘）不得依赖随设置台销毁的对象。撤回只针对「随设置台作用域」这一正面要求，
  不触及探针边界。
- **复评轮盘预热策略** → 否，维持。预热产物可回收（有测试锁定），且启动与常驻态的托管堆同量级——
  它是延迟与内存的权衡，不是泄漏，没有可回收性缺口要补。
- **撤回决策 3 的作用域要求，保留判据与探针边界** → 采纳。

## Consequences

- **主题状态、调色板缓存与系统深浅色监听在进程常驻**：设置台关闭期间仍持有主题引擎状态、
  调色板字典缓存与 `UISettings` 监听实例。这是可接受的残留，其规模见动机 2；
  常驻判据（ADR-0039 决策 2）不因本残留而失真，因为该判据给出的是必要条件而非禁止清单。
- **深浅色探针边界不变**：轮盘与托盘的深浅色读数仍经宿主注入的无状态 `Func<bool>` 探针，
  不新增对 `IThemeService` 的消费边。
- **语言字典维持 Application 级单份**：`{DynamicResource}` 数据源不随设置台开关增删，
  声明式文案在设置台关闭期间仍有源。
- **该要求以新测量为准可重开**：若将来常驻重量被压到托管侧占主导，或主题装配路径取得可摘挂的
  时序保证，可重开作用域化；重开时重新测量，不沿用本文的结论。
