# 文档体系的口径与红线：第一读者是 agent，行数与 ADR 编号身份退出决策

> Status: Active
>
> 现状正典：`docs/agents/docs-conventions.md`（文约与机检口径）；入口 §6 是它的指针。

## 动机

1. **读者已经变了，口径没变**：`docs/` 的第一读者是 agent——按任务单篇加载、无记忆、照字面执行。而既有口径是入口 §6 的十一条人类向散文约定，它已经失守过一次：§6.7 禁止完成态流水，`layout.md` 用「无旧集与壳工程」这种换皮写法绕过了机检的六词黑名单。
2. **两种读者的失败模式不对称**：人类读到与代码不符的文档会起疑核查；agent 照做，且失败时未必归因到文档。同一份重复陈述，人类会去核对，agent 读到哪份是随机的。所以失真与重复对 agent 的伤害都高于对人类。
3. **指针化的成本在读者侧不对称**：人类跳转近乎零成本；agent 每次跳转是一次工具调用加一份新上下文，还可能跳不到就凭印象猜。
4. **精简缺判据**：遗留的都是语义级问题（同一事实多处陈述、现状与目标态混排、失真），而"清单型 / 约束型"的语义分类只回答了"正典在哪"，没回答"别处该留多少"。

## Considered Options

- **口径继续留在入口 §6，只把词表补长** → 否：散文约定装不下正例与反例，而反例是词表的来源；换皮写法正是靠"换词"绕过黑名单的。
- **口径抽成独立文约、§6 收敛为指针** → 采纳：文约同时装得下判据、正反例与机检词表，测试可直接消费，人也能读。
- **指针化一律照语义分类执行（清单型即指针）** → 否：会把禁令与边界也指针化，读者缺了它就做错动作。
- **指针化按「缺失是否致误」取舍** → 采纳：判据落在读者的动作后果上，与读者序位的判断一致。
- **给精设行数闸（如降到某数值才算完成）** → 否：会诱导把约束型规则也指针化、以及因难写而删规范；结构化重排还会增加行数却降低误读。
- **合并同题 ADR（如 0030 并入 0035）** → 否：全仓约 392 处 `ADR-NNNN` 引用横跨 83 个文件，并号会让引用与 git 历史错位；被取代改头部状态即可表达同一件事。
- **ADR 也按执行者口径瘦身（只留选择与指针）** → 否：ADR 的读者角色是"要不要推翻这个决策"，四要素不完整就失去存在理由，会退化成规范的第二份副本。

## Decision

1. **口径正典独立成文**：`docs/agents/docs-conventions.md` 承载写作口径、正反例、机检词表与豁免清单；入口 §6 收敛为一条指针。
2. **失真优先于重复**：与代码不符是错误而非冗余，发现即修；凡可机械核验的失真（路径存在性、类型名存在性、常量归属、ADR 头部状态）一律落断言。
3. **零流水**：文档不承载时间维度，"已落地/已撤销"与「无旧集」这类换皮写法同等禁止。
4. **正典唯一 + 引用就近**：语义分类决定正典在哪，**缺失是否致误**决定别处留多少。
5. **反例就地、正例留在本域正典**：边界示例 ≤3 行就地保留；教学式正例留在其所属领域的正典叶，本文约只收文档写作自身的正例。
6. **目标态分治**：叶子只许在「目标态与差距」节承载目标态，行内标记只用 `规划：` / `as-built：`；ADR 不承载待建设清单。
7. **ADR 编号身份不可动**：不合并、不改号、不删号；被取代只改头部 `Superseded by NNN` 并保留残值。
8. **行数退出决策**：进度以失真项 / 重复项 / 越界项计数。
9. **红线**：`CONTEXT.md` 术语条目、入口 §2 路由表结构、`DocInvariantTests` 断言本身、已声明正典的清单不因精简而移除。
10. **豁免集中**：机检白名单只住文约的「豁免清单」节，每条带理由，不硬编码在测试里。

## Consequences

- 文档规则有了两处所在：入口 §6 是指针、文约是正典，读者需知道这一分工。
- 「缺失是否致误」要逐条判断，比"一律指针化"慢，且判断须在 issue 里留痕。
- 机检是代理指标：语义级历史叙事抓不住，仍靠评审；词表会随清理推进而增长，加词前须先清理到全绿。
- ADR 不追求最小体积：四要素与取证载荷保留，收益低于架构叶子的清理。
- 精简的收益不再能用行数交代——代价是解释成本上升，好处是可用性不会被指标反噬。
