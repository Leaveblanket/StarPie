# 触发键开放配置面:鼠标五键选择,运行态配置实时生效

**状态**:accepted

**日期**:2026-09-19(对齐上游 §2.5/2.10,issue #220)

## 背景

ADR-0052 裁定「触发键在栈内参数化(默认右键,**不暴露配置面与 UI**)」。上游 WinPieGestures 有完整的触发键配置面(录制卡 + 实时硬件感知回显),且其 config.json 的 `TriggerButton` 键与之同名。「输入侧对齐」批次重新裁决此项:**配置面开放**,栈内参数化升级为「运行态配置 + 每事件实时读」。

## 决定

- **配置面**:设置台「触发与场景」页新增触发键录制卡——鼠标五键(左/右/中/侧1/侧2)单选、当前生效键徽章、恢复默认。录制交互取**选择式**而非上游的按键捕获式:上游录制流的 ESC 取消、修饰键过滤、组合键都属键盘捕获侧(ADR-0052 已整体否决),借道即破「单鼠标输入线」约束。
- **配置形态**:config.json 新增 `TriggerButton` 字符串键,值域与上游同名同值(`LeftButton`/`RightButton`/`MiddleButton`/`XButton1`/`XButton2`),上游侧配置可平移读入;缺键与非法值一律回退右键(词表 `TriggerButtonNames`,解析 `TriggerButtonParser` 驻捕获侧,模型层不依赖 SharpHook)。
- **生效通路**:与 `WheelGestureEngine` 每次决策实时读配置同哲学——`MouseInputHook` 构造参数改为触发键**实时读数提供方**(`Func<MouseButton>`),每按下/抬起事件调用一次;设置台写运行态配置后无需任何推送即生效。组合根把测试实例的命令行覆盖(`--trigger-button`,ADR-0052 既有入口)**折叠进提供方**并保持其高于配置的优先级。
- **改键瞬间的在途交互**:按下/抬起以**按下时接管的键**配对收尾——抬起仍归原交互,补发点击补的是当初按下的键,不会错注入新配置键;轻点=补发点击的语义对五键一致(左键作触发键时,轻点即普通点击,无长按呼出的强制语义——该语义随长按呼出整体移除)。
- **排除项不变**:键盘触发键、修饰键组合触发不引入(ADR-0052 键盘侧否决条款维持有效);每应用专属唤醒键(对齐清单 §2.14)不在本决定内。

## 后果

- `AppConfig` 新增 `TriggerButton`(默认 `RightButton`),旧配置缺键自然回退,零迁移。
- `MouseInputHook` 的触发键由构造期定值改为逐事件解析(短字符串 switch,钩子线程开销可忽略);构造签名变化由编译器强制过一遍调用面(贡献者 + 测试)。
- ADR-0052 的「不暴露配置面与 UI」条款由本决定推翻,该 ADR 其余条款(单钩子、抑制同步、回放窗口、看门狗、键盘侧否决)不变。
- e2e 新增触发页配置面用例;`--trigger-button` 覆盖入口及其 e2e 价值(侧键不弹菜单)保持原样。
