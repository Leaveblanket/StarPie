# 插件界面文案来源：字面量显示名成员与宿主键缺键可见

> Status: Active

## 动机

1. **`TitleKey` 一字段两义，而现状已经在用第二种含义**：五个插件 UI 描述符只给「键」，
   宿主一律用自己的 resx 解析。但随包样例插件交出的是中文字面量（`"UI 示例"`），
   靠 `GetString` 缺键回退键名而原样显示——行为正确，却依赖一条没人承认的巧合：
   该字段既可能是宿主文案键，也可能是显示名本身。
2. **缺键静默，第三方无从察觉**：`GetString` 缺键回退键名是明文语义，于是插件要么只能用
   宿主词汇命名自己的界面，要么界面直接显示 `"MyPluginSectionTitle"` 而无人报错。
3. **插件没有自己的文案机制**：插件包内无 resx、无取词面（`ILocalizationService` 驻宿主集，
   对插件编译期不可见），插件无法自持多语言文案表；而 `plugins.md` 承诺的
   「随包文案文件 + 插件面取词」零实现，却以现行规范形态存在。
4. **描述符是 positional record，追加构造参数即二进制破坏**：插件按编译产物装载，
   改动构造签名要拦下全部在网插件（主版本递增）。插件面的扩展只能走 init-only 属性。

## Considered Options

- **落目标态：插件自带文案表 + 插件面取词契约 + 随包文案文件的打包规则** → 否。
  它要同时动三处：插件面新契约、打包链路（只平铺复制主产物，culture 子目录进不了包）与 ALC 的
  卫星资源政策。而要闭合的缺陷是「插件界面可能静默显示原始键名」——加一个描述符成员即可闭合，
  不必然连带付出装载面与分发面的改动。这笔代价应在真有插件需要多语言界面时一次付清。
- **描述符改收显示名（删 `TitleKey`）** → 否。插件面加载侧 additive-only，删除既有成员即主版本
  递增，为清一个字段而拒掉全部在网插件，代价与收益不成比例；且会永久失去宿主侧解析插件文案的能力。
- **维持宿主 resx 约定、补缺键告警** → 部分采纳。它解决了「不静默」，但插件仍只能用宿主词汇，
  字面量路径也没有正式表达。
- **描述符加 init-only 显示名成员 + 语义穿透目录登记 + 注册期缺键可见** → 采纳。
  字面量有了正式表达，键路径保留宿主 resx 解析，失败不再静默。

## Decision

1. **五个描述符（页 / 设置区块 / 菜单项 / 窗口 / 命令）新增 `DisplayName`**（init-only、可空），
   语义是**字面量显示名**、语言无关；`TitleKey` 保留为宿主 resx 文案键（持久兼容面），
   两者**不可同时为空**。显示名让插件不必再借宿主键位表达字面量。不新增描述符、不改构造签名。
   逐条约束见 [plugin-contracts.md](../architecture/plugin-contracts.md) §2 约束 9。
2. **优先级单一**：`DisplayName` 非空取之；否则 `TitleKey` 经宿主 resx 解析；解析不到即按字面量
   显示并在**注册时告警**（经 UI 装载结果的告警集合回传宿主日志，自动带 plugin id，渲染路径不重复
   告警）。条文同上条。
3. **语义区分穿透到目录登记**：插件页的显示名随 `NavigationPageRegistration` 一并携带，不把
   显示名归一塞进 `TitleKey` 槽——归一等于把「字面量恰好命中宿主键名即被翻译」的歧义留在管道里。
   插件文案解析收成一个共用件，注册侧与渲染侧同源。
4. **插件自持文案表（插件面取词契约、随包文案文件与其打包规则）留待生态化阶段**；
   `plugins.md` 的对应条款必须显式标注为规划，不得再以现行规范形态存在。
5. **如实登记渲染状态**：宿主当前渲染页面 / 设置区块 / 托盘条目三处标题；窗口与命令描述符的
   `TitleKey` 不由宿主渲染（窗口标题由插件的窗口设置，命令标题只作 id 路由）——两处保留为兼容面
   并如实登记，不假装它们是生效的文案入口。渲染点登记见
   [plugin-contracts.md](../architecture/plugin-contracts.md) §2 约束 9。

## Consequences

- **残留**：插件把字面量塞进 `TitleKey`、而该文本恰好等于宿主 resx 某个键名时，仍会被翻译成宿主
  译文。这是一字段两义的固有代价，彻底消除需要删除 `TitleKey`（主版本递增）；
  注册期告警已把作者引向 `DisplayName`。
- 新增插件面成员属 additive：UI 侧 ABI 次版本递增，在网插件与随包清单无需改动。
- UI 托管层为做缺键判定需要文案表探针（只读取词），因此多一条对本地化服务的只读依赖；
  该依赖不引入日志面——告警经装载结果回传，由宿主侧记录。
- 三处渲染点的标题解析收敛到同一规则，后续新增插件界面面（例如窗口标题改为宿主托管渲染）
  沿用同一优先级。
