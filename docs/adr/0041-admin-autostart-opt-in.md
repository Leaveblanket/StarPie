# 以管理员身份开机自启：注册表自启之外补一条任务计划程序路径（取代 ADR-0040 决策 2）

> Status: Active（决策 1 的自启落位被 [ADR-0042](0042-privilege-routes-two-only.md) 修订；
> 那颗任务的即时触发形态见 [ADR-0043](0043-elevated-instance-takeover.md)）
>
> 本文**取代** [ADR-0040](0040-startup-privilege-policy.md) **决策 2**（"不提供始终以管理员身份启动的偏好持久化"），
> 其余决策（1 的 asInvoker、3 的备选触发条件、4 的静默自启承诺、5 的边界行为归位、6 的已落地三项）不变。
> 契约正典：`docs/architecture/shell.md`（自启面）、`docs/architecture/config.md`（新字段）；
> 术语见 `CONTEXT.md`（提权 / 提权自启）。

## 动机

ADR-0040 决策 2 的否决理由原文是"开关一旦打开即把硬强制的全部代价搬回，而相对现状的唯一收益是省掉用户点一次托盘"。
这条理由把**代价的形态**锁死在了 ADR-0040 写成时的选项集里（manifest 强制提权、或每次启动 `runas`），
而 Windows 还提供第三条路径：**任务计划程序**——`/rl highest` 让任务以最高权限运行，提权动作由
任务计划程序服务在触发时完成、**不弹 UAC**；`/sc onlogon` 登录即起（现行命令形态见
[shell.md](../architecture/shell.md) 关键流程 3）。即：ADR-0040 列的"每次 UAC"与"开机自启从静默变为
登录弹窗"这两笔代价，在这条路径上**根本不发生**。

ADR-0040 列的另外两笔代价，当时的处理方式是：子进程继承管理员由降权启动缓冲，插件提权由插件管理页
警示披露。前者已由 [ADR-0042](0042-privilege-routes-two-only.md) 取消（子进程继承管理员成为提权形态的
既定代价）；后者保留——插件管理页的提权警示是 [ADR-0029](0029-plugin-trust-model.md) 要求的披露落点。

于是四笔代价只剩一笔真正要付：**自启机制的形态从 HKCU Run 变成计划任务**（创建/删除该任务本身需要管理员，
故用户拨这个开关时会弹一次 UAC；标准用户账号没有管理员凭据时该开关必然失败）。

## Considered Options

- **维持 ADR-0040 决策 2（不提供）** → 否。它的成立前提是"提权必然伴随每次 UAC"，任务计划程序路径已证否；
  且上游 `SoftBlack42/StarPie` 以同一机制长期实装（`AutoStartAsAdmin` + `schtasks /rl highest`，
  设置页文案标注"推荐"），说明这不是纸面可行。
- **manifest `requireAdministrator` / `highestAvailable`** → 仍否（ADR-0040 已论证：每次 UAC、拒绝即不启动、
  标准用户账号每次要凭据、混合完整性级别成为常态）。本次不碰清单声明。
- **把提权自启做成默认开启** → 否。默认值保守：提权把插件的爆炸半径抬到机器级，
  应由用户在看到代价说明后主动选择，而不是替他决定。
- **保留用户手工建任务的说明文档（不写代码）** → 否。"用户自己会去建计划任务"不是可交付的体验；
  且形态细节（`/rl highest` + `onlogon` + `/delay`）恰恰是容易做错的部分。
- **注册表 Run 之外叠加计划任务（采纳）** → 本 ADR 记录时注册表项同时照写作兜底；该兜底已被
  [ADR-0042](0042-privilege-routes-two-only.md) 取消。

## Decision

1. **新增用户可选的提权自启形态**：设置页「以管理员身份开机自启」开关（默认关闭）。
   打开时建任务计划程序任务（`/rl highest /sc onlogon`），关闭时删任务、回落普通权限自启；
   关掉总开关「开机自启」时两者一并删除。现行落位规则（两形态互斥）正典见
   [shell.md](../architecture/shell.md) 关键流程 3，该落位由 [ADR-0042](0042-privilege-routes-two-only.md) 修订。
2. **提权自启蕴含自启**：直接打开提权形态会把「开机自启」一并打开，用户不必先手工开自启。
3. **状态以系统实况为准**：界面开关的提权形态读自**计划任务的实况**（`schtasks /query` 的退出码），
   不读配置——用户在任务计划程序里手工删掉任务时，开关必须如实显示"没在运行"。
   `config.json` 的 `AutoStartAsAdmin` 只记录用户上一次成功落位的意图。
4. **失败不静默**：创建/删除任务需要管理员，非提权态经 `runas` 弹一次 UAC；
   用户取消（`Win32Exception` 1223）或账号无管理员凭据时，**不落盘该偏好**，开关拨回实况并给出提示。
   无任务可删时不白弹一次 UAC。
5. **dev 实例隔离**：dev 的计划任务名带独立后缀（`StarPie_AdminAutoStart_Dev`），
   与配置目录的 dev 分支同口径，绝不与正式版共用。
6. **不影响 ADR-0040 决策 1**：仍不写 `requestedExecutionLevel`，仍是 asInvoker；本任务被触发时
   由服务完成提权，进程自身不带任何清单声明。这颗任务同时是即时提权的载体
   （见 [ADR-0043](0043-elevated-instance-takeover.md)）。

## Consequences

- 用户首次打开该开关要付一次 UAC——这一次是"创建任务"的一次性授权，不是每次启动的常税；
  此后每次登录静默以管理员运行本条承诺（ADR-0040 决策 4 的"静默自启"）仍然成立。
- 提权形态下的代价与护栏见 [ADR-0042](0042-privilege-routes-two-only.md)：从轮盘启动的程序继承
  管理员令牌（既定代价），插件管理页明示"所有插件同具管理员权限"（ADR-0029 的披露落点）。
- **诊断可见性**：任务创建/删除/查询的失败走 `Debug.WriteLine` + 一次界面提示；
  `schtasks` 的输出不入日志（其文本随系统语言变化，解析不可靠）——排障以退出码与任务计划程序界面为准。
- **本 ADR 不引入自愈**：可执行文件搬家或升级后，任务里的路径会失效（与注册表自启项的失效方式相同），
  不做启动期自动重建——重建需要管理员权限，静默启动时无法提供。
  用户重拨一次开关即可刷新路径（`/f` 覆盖同名任务）。
- 提权形态下子进程继承管理员令牌是既定代价，见 [ADR-0042](0042-privilege-routes-two-only.md)。
